## Design

### Scope (grew at re-plan)

Diarization on the them-stream + `speakers` schema + S1/S2 labels; bounded capture→analyzer buffering with drop counter (G4 pull-in); **RMS signal-strip wiring** (slice-1 debt: "session-state-driven until slice 4 wires real RMS"); **diagnostics stat-grid** (memory MB + dropped-chunks tiles per design/06).

### Decisions (re-plan, 2026-08-07; supersede the 2026-07-17 list)

1. **Engine: chunked-incremental FluidAudio *offline* pipeline** (~10 s windows of accumulated them-audio; FluidAudio's cross-call speaker manager keeps within-meeting identity) behind a `DiarizationEngine` protocol. Whole-file re-runs are disqualified by arithmetic (4 h of 16 kHz Int16 them-audio ≈ 460 MB > G4's 400 MB budget); streaming Sortformer is the engine-internal fallback if the Phase-0 gate shows cross-window identity loss. Speaker keys map to `S1`/`S2`… by first appearance (**amends** the old "Speaker 1/2" — design mockups are source of truth and the 34 pt gutter fits only `S1`). Mic stream is the user by definition; M1 you/them untouched.
2. **Placement: new SPM target `DiarizeKit`** (deps: CaptureKit + FluidAudio; *not* PersistKit — it emits value types and `MeetingPipeline` writes the stores). TranscribeKit stays pure Speech-framework; all model-gated suites live in `DiarizeKitTests`. Chunks arrive in the analyzer's *negotiated* format (Int16 mono 16 k on SDK 26.5, but queried) — DiarizeKit converts defensively to its required 16 k mono rather than assuming.
3. **Attribution is post-hoc, two channels.** Live: `TranscriptStore.speakerLabels: [Segment.ID: String]` observable map + `setSpeakerLabel` (cleared on `reset()`); gutter resolves `label ?? "Them"/"You"`; volatile lines never consult the map — G1 untouched by construction. DB: one batched sweep in `MeetingPipeline.stop()`, after `segmentWriter.flushAndStop()` (kills the insert/UPDATE race with the debounced writer) and before `endMeeting` (the post-meeting agent always sees labels; a mid-meeting crash loses labels but keeps the transcript — same durability class as M1, accepted). The diarizer consumes audio via its fan-out branch and finals via a second `finalsStream()` consumer (the store's continuation dictionary supports N consumers), attached pre-capture under the same binding constraint as the SegmentWriter. AgentKit boundary: `MeetingStore.attributedSegments(for:)`; one-line change at `PostMeetingAgent.swift:96`.
4. **Bounded fan-out lives in CaptureKit** (**amends** old decision 4's "fan-out in TranscribeKit" — the operator has nothing STT-specific and the RMS tap wants it too): `BoundedAudioFanOut` — one forwarding task eagerly drains the source stream (capture's internal `.unbounded` streams never accumulate) into N `.bufferingNewest(100)` branches (~10 s of audio at the observed ~0.1 s chunk cadence; ~320 KB ceiling per branch), per-branch lock-protected drop counters from the yield result's evicted element. Applied at the `MeetingPipeline.start()` seam for both sources: mic → [STT], system → [STT, diarizer]. The latency harness re-routes through the same operator so G1 measures the production shape. Drop-oldest + a counted, surfaced gap is the honest stall behavior — replaying a >10 s backlog into STT would produce garbage timing anyway.
5. **RMS:** computed per-chunk inside the forwarding loop (both sources — design wants per-source levels: you = amber, them = slate) → lock-protected `SignalLevelMeter` → `coordinator.currentSignalMeter` → `SignalStripView` polls at 100 ms via `TimelineView`. Tick shape, voice colors, and the reduce-motion static-dot collapse are preserved (level modulates tick scale only).
6. **Models: consent-gated one-time download (author ruling 2026-08-07).** `DiarizationModelStore.isInstalled` (checks both `.mlmodelc` bundles under `~/Library/Application Support/FluidAudio/Models/speaker-diarization/` — Notes 2a corrected the path) is the one availability seam, consulted at meeting start in `productionPipeline`; `download()` is called only behind the explicit Settings affordance naming the endpoint and ~129 MB size (the button *is* the consent). Models absent ⇒ the meeting runs exactly as M1 with zero network — the G6 default is preserved and the download is a documented, user-approved exception. (The planned `DiarizationAvailability` enum collapsed to the `isInstalled` bool — two states don't earn a type.) Tests needing real models gate skip-not-fail: `@Suite(.enabled(if: hasModels))` (the `LiveCredentials.hasDeepSeek` precedent).
7. **Speaker roster surface: deferred** — not drawn in any approved mockup; the gutter labels carry the information and history rows get a speaker count in slice 5. Needs a design addendum if ever wanted.

### FluidAudio vetting record (desk half, 2026-08-07)

## Notes / dead ends

1. 2026-08-07 — **Phase-0 hard gate PASSED on the first voice pair** (Daniel en_GB / Samantha en_US, 10 alternating ~6–7 s turns, 0.7 s gaps, 69.6 s total, 16 k mono Int16). Real FluidAudio (`DiarizerManager.performCompleteDiarization`, pyannote + WeSpeaker models, one-time 20.9 s download): exactly 2 hypothesis ids, every A-turn → id 1 and every B-turn → id 2, majority coverage 55–99 % per turn, in **both** whole-file and sequential-10 s-window modes — the windowed run's attributions are identical to whole-file, confirming decision 1's cross-window identity assumption (the manager's persistent `SpeakerManager` carries identity across `performCompleteDiarization(_:atTime:)` calls, which is exactly the production chunked shape). Windowed run cost 0.5 s for 69.6 s of audio (~140× real-time) — the ~10 s window cadence has enormous headroom. Fixture + known schedule committed at `Tests/DiarizeKitTests/Fixtures/{two-voices.wav,schedule.json}`; check 1's oracle asserts against that schedule with majority-overlap purity. Gate harness was scratchpad-only (not committed) per plan; generation recipe: `say -v <Voice> -o utt.aiff` per turn → `afconvert -f WAVE -d LEI16@16000 -c 1` → concatenated with 0.7 s silences, schedule emitted alongside.
2. 2026-08-07 (build findings) — (a) **The web-sourced model path was wrong**: on macOS the cache is `~/Library/Application Support/FluidAudio/Models/speaker-diarization/`, not `~/.cache/fluidaudio`; and `DiarizerModels.load(from:)` **falls back to downloading** — the only genuinely network-free loader is `load(localSegmentationModel:localEmbeddingModel:)`, which is what `DiarizationModelStore.loadInstalled()` uses; the consent gate is real by construction. (b) **`.bufferingNewest` semantics confirmed** — yield reports the evicted element, so the exact drop counter needs no hand-rolled ring buffer (the plan's flagged fallback is moot). (c) **Terminated branches count as drops**: a consumer that *discards* its branch stream (early engine exit) makes yields return `.terminated`, not `.dropped` — found when the first stall oracle read 0; the fan-out counts both, since either way the chunk reached no one. (d) `AVAudioFile.read` **throws `.nilError` when called at exact EOF** — fixture readers must break on a short read (the M1 precedent already did; the new DiarizeKit reader learned it the hard way). (e) Live labels never flip: the session's incremental pass only attributes still-unassigned segments; `finalize()`'s full recompute is what the DB gets. (f) Diarizer-session construction is `Task.detached` in `MeetingPipeline.start()` — the first-ever CoreML load takes ~8 s and must not block the main actor; construction failure degrades to an M1 meeting by design (test-pinned).
3. 2026-08-07 (fresh-context critic pass at ship) — one should-fix confirmed: `stop()` running to completion while `start()` was suspended in the multi-second detached diarizer construction would orphan the freshly built session (live CoreML load) past teardown — G4 risk, plus the narrower pre-existing ghost-meeting window the critic traced to M1's stop-doesn't-await-start design. Fixed with a `stopped` guard immediately after the construction await (check-and-adopt is one synchronous MainActor stretch, so no re-interleave); regression test `stopCompletingDuringDiarizerConstructionOrphansNothing` uses a weak-box leak oracle and was **mutation-proven** (guard disabled ⇒ red). Everything else scrutinized came back clean: G1 volatile path structurally unaffected (STT branch yielded before diarizer branch, yields never suspend), drop accounting, buffer-sharing contract, append-only invariant, ephemeral disk isolation, log hygiene (no transcript text in logs), G6 no-download guarantee, schema v4. Two sub-threshold observations recorded by the critic, not acted on: the signal strip's animation keys on the level *sum* (harmless snap in a vanishing edge case); the 64 MB footprint test could in principle collide with a concurrent suite's large dealloc (fix only if it ever flakes). The pre-existing stop-vs-start window on the *writer* side (M1 design) is left as-is — narrower, no heavy resource, and a structural fix (stop awaiting start) belongs to a deliberate pipeline-lifecycle change, not a slice tail.
